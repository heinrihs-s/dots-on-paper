# A ten-user beta

Recruit consenting technical assistant users; existing TRMNL owners are useful for the separate hardware study. Begin with the completed-task recipe. Run the same versioned runtime and guide for everyone. Record failures and intervention instead of excluding unsuccessful attempts.

Use anonymous participant IDs and the local [record template](../examples/beta-observations.csv). Record OS/Python/client versions, install start and first real browser result, minutes of help, and failure category. A local test card is not activation. Do not collect keys, private URLs, calendars, answer text or conversation history.

Hardware timing begins after the device is online. Record exact model, firmware, route and refresh settings; measure from actual source publication to observed panel output. Record upload/fetch receipt separately. Repeat after bridge restart and a temporary delivery failure. Photograph only deliberately selected content with the owner's publication permission.

On day seven, ask which real result was useful, whether it was noticed later, how many days it was used, whether setup had to be repeated and whether the owner intends to keep it. Count usage during days 5–7 against activated users; recruit until ten have activated. The small-cohort gates are 8/10 unaided within ten minutes, three independent physical reproductions, and at least 5/10 retained at day seven.

No telemetry or scheduled outreach is added by this implementation. Save consented aggregates in a dated local record. Promotion proceeds after the [roadmap gates](roadmap.md) pass; reach and stars remain separate from working installations.
