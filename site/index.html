Run the bridge on your computer, then choose your connection.
Python 3.11+ and Node.js 22+ required.

Start with the bridge.

Clone the repo and run setup. It installs the package and creates private keys on your computer.

Install
git clone https://github.com/heinrihs-s/dots-on-paper.git
cd dots-on-paper
python tools/setup.py
Start the bridge
.venv/bin/python -m dots_on_paper --data-dir ./data

Use python3 if your system needs it. Open 127.0.0.1:9035 on your computer and select data/credentials.json in the local preview. Keep that file private.

Install Dots on Paper from the Plugins Directory. Point DOTS_CONFIG_FILE to the running bridge’s credentials, then start a new conversation. The guide includes direct MCP configuration.

For a cloud ChatGPT dot

Use a private Secure MCP Tunnel. It needs a tunnel ID, a Platform runtime API key, and the appropriate workspace permissions. Keep the bridge and tunnel running.

Connect your dot

A little home
on your TRMNL.

Use an existing BYOS device and a bridge address reachable from its network. Choose the native TRMNL X profile or the original TRMNL profile.

  1. Configure your LAN address and allowed hosts before starting the bridge.
  2. Set your existing DOTS_TRMNL_DEVICE_ID and DOTS_TRMNL_ACCESS_TOKEN.
  3. Configure the device’s BYOS origin separately. The bridge advances a thinking pose per wake, then returns one stable result filename.
Windows · replace YOUR_LAN_IP
$env:DOTS_HOST = '0.0.0.0'
$env:DOTS_PUBLIC_URL = 'http://YOUR_LAN_IP:9035'
$env:DOTS_ALLOWED_HOSTS = 'YOUR_LAN_IP,localhost,127.0.0.1'

Thinking uses a 15-second sleep; the answer returns to 60 seconds. Boot, Wi-Fi and drawing add time. Stock TRMNL X can flash between frames. The cloud private-plugin route is separate.

TRMNL configuration

Give your home
assistant a face.

A custom integration provides an image entity, reply and status sensors, character selection, actions, and a new-reply event.

  1. Copy custom_components/dots_on_paper into HA’s /config/custom_components/.
  2. Restart Home Assistant. Open Settings → Devices & services → Add integration → Dots on Paper.
  3. Enter the reachable bridge address, its publishing key, and your screen profile.

The image updates only while thinking and holds the completed result. The guide also forwards actual replies from an HA conversation agent.

Manual install for now; HACS listing is pending. Live Home Assistant verification is still needed.

Home Assistant setup

Your panel.
Your pace.

The ESPHome example polls display metadata, downloads successive thinking frames, then draws the completed reply once.

  1. Merge the example into your board configuration. Use your panel’s actual pins, model, dimensions and busy signal.
  2. Set the display ID to eink_display and its update_interval to never.
  3. Keep image and metadata URLs plus the read-only image token in secrets.yaml.

Schema checked with ESPHome 2026.9.1. The default redraw interval is 30 seconds; shorten it only if your exact panel and driver support it. This is a merge fragment, not complete firmware.

A few things
before you build.

Small screens have their own pace.
Here’s what to expect.

Will it show every ChatGPT reply automatically?

The dot publishes through an enabled MCP tool. There is no automatic feed of every reply. Ask it to set thinking when it starts and publish a short version of the actual answer when it finishes.

Can e-ink really animate?

Yes, by drawing successive images. The panel and driver set the pace. A sleeping device may miss a short thinking phase, and stock TRMNL X can flash. The website and films run faster for demonstration. OpenEPaperLink’s portable example sends only the final result.

What has been tested?

The bridge, renderer, MCP adapter, HA image lifecycle and installed package have passing tests. ESPHome configuration validation passed. A live dot account, physical e-ink panels and a running HA installation still need verification. Read the verification record.
